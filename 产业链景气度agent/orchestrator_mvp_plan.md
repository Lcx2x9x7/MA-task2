# 产业链景气度 MVP Orchestrator 方案

## 1. MVP 是什么

MVP 是 Minimum Viable Product，中文可以理解为“最小可行版本”。

在本项目里，MVP 不是把所有指标、所有 Agent、所有数据源一次性做完，而是先做一个能稳定跑通的版本：

```text
输入：自然语言问题，例如“新能源汽车产业链分析”
输出：该产业链景气度评分、等级、主要依据、政策信号、实时市场信号、数据置信度
```

本阶段只做五条产业链：

| 产业链 | 产业链 ID |
|---|---:|
| 半导体产业链 | 78492 |
| 低空经济产业链 | 1921 |
| 机器人产业链 | 119013 |
| 生物医药产业链 | 36112 |
| 新能源汽车产业链 | 70258 |

## 2. 总体原则

1. Agent 数量控制在 3 个以内。
2. 实时数据只保留一个来源，避免系统过重。
3. 离线数据优先使用权威来源，提前爬取并缓存。
4. A 股数据不直接全市场检索，先映射到板块，降低噪声。
5. 最终输出必须带数据来源、时间戳、置信度。

## 3. 推荐 Agent 设计

### 3.1 主控不算 Agent

`orchestrator.py` 是主控程序，负责调度，不负责具体分析。

```text
orchestrator.py
  -> Interpretation Agent
  -> Data Tool Agent
  -> Scoring & Report Agent
```

### 3.2 Interpretation Agent

作用：

把用户自然语言问题解析成结构化任务。

输入：

```text
新能源汽车产业链分析
```

输出：

```json
{
  "chain_id": "70258",
  "chain_name": "新能源汽车产业链",
  "intent": "chain_booming_evaluation",
  "keywords": ["新能源汽车", "动力电池", "锂电池", "充电桩", "智能驾驶"],
  "board_candidates": ["新能源汽车", "锂电池", "动力电池", "充电桩"],
  "need_realtime": true
}
```

这个 Agent 重点做三件事：

1. 判断用户问的是哪条产业链。
2. 从产业链表中取对应节点和上中下游结构。
3. 生成后续数据抓取关键词和板块候选。

### 3.3 Data Tool Agent

作用：

负责调用工具和读取缓存，不做主观判断。

输入：

```json
{
  "chain_id": "70258",
  "chain_name": "新能源汽车产业链",
  "keywords": ["新能源汽车", "动力电池", "锂电池"],
  "board_candidates": ["新能源汽车", "锂电池", "动力电池"]
}
```

输出：

```json
{
  "chain_structure": {},
  "nbs_metrics": [],
  "policy_docs": [],
  "realtime_board": {},
  "data_quality": {}
}
```

它只做确定性工作：

- 读取产业链节点表。
- 读取提前爬好的国家统计局数据。
- 读取提前爬好的发改委/工信部政策文件。
- 调用一个实时板块行情接口。
- 记录来源、时间戳、字段缺失情况。

### 3.4 Scoring & Report Agent

作用：

根据规则评分，并把结果解释成人能看懂的报告。

输入：

```json
{
  "chain_structure": {},
  "nbs_metrics": [],
  "policy_docs": [],
  "realtime_board": {}
}
```

输出：

```json
{
  "chain_id": "70258",
  "chain_name": "新能源汽车产业链",
  "score": 76.5,
  "level": "较高景气",
  "confidence": "中高",
  "drivers": [],
  "risks": [],
  "evidence": []
}
```

它负责：

- 计算宏观/行业景气分。
- 计算政策支持分。
- 计算上中下游敏感性分。
- 计算实时市场分。
- 做风险和置信度校验。
- 输出 Markdown 或 JSON 报告。

## 4. 主程序接口规范

主程序文件：

```text
orchestrator.py
```

命令行调用：

```bash
python orchestrator.py --question "新能源汽车产业链分析"
```

注意：`orchestrator.py` 和 `--question` 之间需要有空格。用户示例里的 `python orchestrator.py--question` 在标准命令行里会被识别成错误文件名，除非额外做兼容。

建议支持参数：

```bash
python orchestrator.py --question "新能源汽车产业链分析"
python orchestrator.py --question "低空经济产业链景气度怎么样" --output outputs/low_altitude.md
python orchestrator.py --question "半导体产业链分析" --format json
```

`argparse` 规范：

```text
--question   必填，自然语言问题
--output     可选，输出文件路径
--format     可选，markdown/json，默认 markdown
--no-realtime 可选，关闭实时行情调用
```

## 6. 数据层设计

### 6.1 产业链节点表

这是最干净的内部结构数据，应该作为系统主索引。

使用字段：

| 字段 | 用途 |
|---|---|
| 产业链 ID | 匹配五条产业链 |
| 产业链名称 | 匹配用户问题 |
| 节点代码 | 节点唯一标识 |
| 节点名称 | 生成政策、统计、板块关键词 |
| 节点层级 | 判断节点颗粒度 |
| 节点上中下属性 | 判断上游、中游、下游敏感性 |
| 分值 | 作为节点重要度先验 |
| 1-5 级节点路径 | 构建产业链树 |

### 6.2 国家统计局数据，提前爬取

来源：

```text
stats.gov.cn / data.stats.gov.cn
```

用途：

- 判断宏观景气方向。
- 判断行业周期。
- 对上游、中游、下游进行敏感性比较。

建议预爬字段：

| 类型 | 指标示例 | 用途 |
|---|---|---|
| 宏观 | GDP、PMI、PPI、CPI | 大盘景气背景 |
| 工业产量 | 集成电路、工业机器人、汽车、新能源汽车相关产量 | 供需景气 |
| 工业企业 | 收入、利润、库存、应收账款 | 行业盈利和库存压力 |
| 投资消费 | 固定资产投资、社会消费品零售 | 下游需求环境 |

和产业链字段的关联方式：

```text
产业链名称 + 节点名称 + 节点上中下属性
```

示例：

```text
新能源汽车产业链
  上游：电池材料、锂电池 -> 关注 PPI、原材料价格、相关工业利润
  中游：整车制造、电池制造 -> 关注产量、产销、利润
  下游：充电、出行、消费 -> 关注零售、投资、消费和政策需求
```

### 6.3 发改委/工信部政策文件，提前爬取

来源：

```text
ndrc.gov.cn
miit.gov.cn
```

用途：

- 判断政策支持或限制。
- 辅助判断行业中期成长性。
- 对具体节点打政策标签。

建议预爬字段：

```json
{
  "title": "",
  "publish_date": "",
  "source": "NDRC/MIIT",
  "url": "",
  "keywords": [],
  "related_chain": "",
  "related_nodes": [],
  "policy_direction": "support/restrict/neutral",
  "policy_strength": 1,
  "summary": "",
  "evidence_text": ""
}
```

政策方向规则：

| 情况 | 标签 |
|---|---|
| 鼓励、支持、试点、补贴、税收优惠、基础设施建设 | support |
| 监管加强、准入收紧、产能约束、安全整治 | restrict |
| 一般性规划、会议、标准宣贯 | neutral |

政策强度规则：

| 政策类型 | 分值 |
|---|---:|
| 国家级规划、重大专项、强制性标准 | 5 |
| 部委正式通知、试点、资金支持 | 4 |
| 行业指导意见、专项行动 | 3 |
| 地方政策、园区政策 | 2 |
| 一般新闻或解读 | 1 |

## 7. 唯一实时数据接口

本阶段只保留一个实时数据来源：

```text
东方财富概念/行业板块实时行情，使用 AKShare 封装调用
```

为什么不用直接全 A 股检索：

1. 全 A 关键词噪声大，容易抓到蹭概念公司。
2. 五条产业链都涉及多个细分板块，个股归属复杂。
3. 板块行情本身已经做过聚合，更适合作为景气边际信号。

建议接口文件：

```text
tools/realtime_board.py
```

对外函数：

```python
def get_realtime_board_signal(chain_name: str, board_candidates: list[str]) -> dict:
    ...
```

返回结构：

```json
{
  "source": "AKShare/Eastmoney",
  "is_realtime": true,
  "fetch_time": "2026-07-18 10:30:00",
  "chain_name": "新能源汽车产业链",
  "matched_board": "新能源汽车",
  "match_method": "config_whitelist/fuzzy_match",
  "pct_change": 1.23,
  "turnover_rate": 2.45,
  "amount": 1234567890,
  "rising_count": 80,
  "falling_count": 20,
  "score": 73.5,
  "confidence": 0.8,
  "raw": {}
}
```

优先级：

```text
1. 概念板块名称匹配
2. 行业板块名称匹配
3. 人工配置兜底
4. 匹配不到则返回缺失，不强行打高分
```

评分方法：

```text
实时市场分 =
  0.50 * 板块涨跌幅分
+ 0.30 * 上涨扩散度分
+ 0.20 * 成交活跃度分
```

实时数据权重建议只占总分 10%，因为它反映的是市场预期，不等同于真实经营。

## 8. 板块是否需要分类

需要分类，不建议直接查全 A。

原因：

```text
产业链 ≠ 一个 A 股板块
产业链包含上游、中游、下游多个节点；
直接关键词搜股票会混入蹭热点、业务占比很低、名称相似但不相关的公司。
```

推荐做法：

```text
产业链节点表
  -> 提取节点关键词
  -> 结合人工配置的核心板块候选
  -> 查询东方财富概念/行业板块
  -> 选出主板块和辅助板块
  -> MVP 只用主板块实时行情
```

五条产业链初始板块配置：

| 产业链 | 主板块候选 | 辅助板块候选 |
|---|---|---|
| 半导体产业链 | 半导体、芯片、集成电路 | 光刻机、先进封装、存储芯片、第三代半导体 |
| 低空经济产业链 | 低空经济、飞行汽车、无人机 | 通用航空、航空装备、eVTOL |
| 机器人产业链 | 机器人、人形机器人、工业机器人 | 减速器、机器视觉、工业母机、智能制造 |
| 生物医药产业链 | 生物医药、创新药、医疗器械 | CRO、疫苗、基因治疗、细胞治疗 |
| 新能源汽车产业链 | 新能源汽车、锂电池、动力电池 | 充电桩、智能驾驶、汽车零部件 |

实际实现时：

```text
先拉取实时板块列表；
再用配置中的候选名称做精确/模糊匹配；
匹配到多个时，优先主板块；
主板块缺失时，用辅助板块加权平均。
```

## 9. MVP 评分指标

为了先跑通，建议先用 5 个指标，而不是 7 个。

| 指标 | 权重 | 来源 |
|---|---:|---|
| 宏观与行业景气 | 35 | 国家统计局预爬数据 |
| 政策支持与限制 | 25 | 发改委/工信部政策文件预爬 |
| 上中下游结构敏感性 | 20 | 产业链节点表 |
| 实时市场景气 | 10 | 唯一实时板块行情接口 |
| 数据可靠性与风险底线 | 10 | 数据完整度、来源可信度、负面政策/风险事件 |

总分：

```text
景气度总分 =
  0.35 * 宏观与行业景气
+ 0.25 * 政策支持与限制
+ 0.20 * 上中下游结构敏感性
+ 0.10 * 实时市场景气
+ 0.10 * 数据可靠性与风险底线
- 重大风险扣分
```

等级：

| 分数 | 等级 |
|---:|---|
| 85-100 | 高景气 |
| 70-85 | 较高景气 |
| 55-70 | 平稳 |
| 40-55 | 承压 |
| 0-40 | 低迷 |

## 10. 三个 Agent 的调用链

```text
用户问题
  |
orchestrator.py
  |
Interpretation Agent
  - 识别产业链
  - 提取关键词
  - 读取产业链节点
  - 生成板块候选
  |
Data Tool Agent
  - 读取 NBS 预爬数据
  - 读取 NDRC/MIIT 政策预爬数据
  - 调用 realtime_board.py
  |
Scoring & Report Agent
  - 计算 5 个指标
  - 生成总分和等级
  - 检查置信度和底线风险
  - 输出报告
```

## 12. 后续扩展

MVP 跑通后再加：

1. 海关数据：用于进口依赖和外需。
2. 招投标数据：用于真实订单。
3. 财报数据：用于利润和价值分配。
4. 专利数据：用于技术景气。
5. 企业层分层：核心层、骨干层、基础层、边缘层。

现阶段不要同时上太多数据源，否则调试成本高，且很难解释每个分数从哪里来。
