# 企业链上地位分层运行说明

当前企业级分层 MVP 只评价一个指标：

```text
链上地位
```

它不做复杂规则匹配，而是从自然语言问题中抽取客户 UID，然后在 `data` 目录下的数据表里精确检索。

## 数据文件

```text
data/产业链.xlsx
data/结算链1.xlsx
data/结算链2.xlsx
```

当前暂未使用：

```text
data/企业财报.xlsx
```

## 运行指令

```bash
python orchestrator.py --question "评估客户UID 3086953029434df7870c1fe17411786920170317111059 的链上地位"
```

默认会调用 LLM，生成面向对公客户经理的经营建议。关闭 LLM：

```bash
python orchestrator.py \
  --question "评估客户UID 3086953029434df7870c1fe17411786920170317111059 的链上地位" \
  --no-llm
```

输出文件默认保存到：

```text
outputs/enterprise_reports/
```

## 评分方法

```text
链上地位 =
  0.60 * 环节关键程度
+ 0.40 * 上下游连接广度
```

### 环节关键程度

来自 `产业链.xlsx`：

```text
产业链名称
节点代码
节点名称
节点层级
节点上中下属性
分值
1-5级节点路径
```

关注企业命中了多少产业链、多少节点、节点层级有多深、节点原始分值有多高。

### 上下游连接广度

来自 `结算链1.xlsx` 和 `结算链2.xlsx`：

```text
客户UID
交易对手客户UID
交易方向名称
现金交易金额区间
现金交易笔数
票据金额区间
票据笔数
现金+票据交易金额区间
现金+票据交易笔数
```

关注唯一交易对手数量、入账/出账方向是否双向、交易笔数和交易金额区间。

## 分层标准

| 得分 | 分层 |
|---:|---|
| >= 85 | 核心层 |
| 70-85 | 骨干层 |
| 55-70 | 基础层 |
| < 55 | 边缘层 |

## 当前限制

- 当前使用 UID 精确检索，因此问题里必须包含完整客户 UID。
- 每次会流式扫描 Excel 大文件，首次查询可能较慢。
- 后续可以生成 UID 索引缓存，把查询速度从分钟级降到秒级。
- 当前分层不是信用评级，也不是授信结论。
